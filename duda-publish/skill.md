# Duda Blog Publisher Skill

You are helping the user publish a blog post to a Duda site via the Duda MCP. The post will be saved as a **draft only** — never call `publish_blog_post`.

## Invocation

`/duda-publish`

---

## Step 1 — Identify the target site

Run `list_sites` to fetch the user's Duda sites. Show them a numbered list of site names and any associated custom domains. Ask which site they want to publish to.

If they already know their site name/ID (the internal Duda identifier), they can skip straight to Step 2.

---

## Step 2 — Collect post details

Ask the user for the following. You can ask for everything in one go.

**Required:**
1. **Post title** — the blog post title (max 200 chars, ideally under 70 for SEO)
2. **HTML content** — the full HTML body of the post. They can paste it directly. Accepted tags: `<p>`, `<h1>`, `<h2>`, `<h3>`, `<strong>`, `<em>`, `<ul>`, `<ol>`, `<li>`, `<a>`, `<img>`
3. **Meta description** — 150–160 character SEO summary for search results
4. **Thumbnail image URL** — shown in blog listing pages. **Must be a full https:// URL** (see image note below)

**Optional but recommended:**
5. **Hero/main image URL** — large header image at the top of the post. Full https:// URL.
6. **Author name** — defaults to site owner if blank
7. **URL slug** — e.g. `my-post-title`. No leading slash, URL-safe characters only. If blank, Duda auto-generates one.
8. **Tags** — comma-separated list e.g. `credentialing, healthcare, payer enrollment`
9. **Publish date** — for scheduling. Format: `YYYY-MM-DDTHH:mm:ss` e.g. `2026-06-01T09:00:00`. Leave blank for no date.
10. **Meta title** — only if different from the post title (for SEO override)

---

## Image note — IMPORTANT

⚠️ **The Duda MCP cannot upload image files.** All images must already be hosted online with a public `https://` URL.

This means:
- If the user's HTML contains `<img src="./images/hero.jpg">` or other relative/local paths, those images **will not display** after publishing. The user needs to upload those images to a CDN, image host, or Duda's own media library first, then provide the public URLs.
- If images in the HTML are already absolute `https://` URLs, they will work as-is.
- The **thumbnail URL is required** — `create_blog_post` will fail without it.

If the user provides local image paths, flag each one clearly and ask them to provide hosted URLs before proceeding. Do not invent URLs or guess.

If the user says they have images in Duda's media library but doesn't know the URL: let them know they can find the URL by opening the image in Duda's editor and copying the direct link.

---

## Step 3 — Validate the HTML

Before posting, do a quick scan of the HTML content:

1. Check all `<img src="...">` tags — flag any that are not absolute `https://` URLs
2. Check for any `<script>`, `<iframe>`, `<style>` or other unsupported tags — Duda will strip these; warn the user
3. Check for very long unbroken strings that may cause layout issues

If there are issues, report them and ask the user to fix before continuing. If everything looks clean, proceed.

---

## Step 4 — Create the draft post

Call `create_blog_post` with:
- `site_name` — the Duda site identifier from Step 1
- `title` — from Step 2
- `content` — the HTML body from Step 2
- `description` — meta description from Step 2
- `thumbnail_url` — from Step 2 (required)
- `main_image_url` — from Step 2 (if provided)
- `author` — from Step 2 (if provided)

This creates the post as a **draft**. Do not call `publish_blog_post`.

If `create_blog_post` returns an error, report the exact error to the user and do not proceed.

---

## Step 5 — Apply metadata

After the draft is created, call `update_blog_post` with the `post_id` returned in Step 4 to set any of the following that were provided:

- `path` — URL slug
- `tags` — array of tag strings
- `publish_date` — ISO datetime string
- `meta_title` — SEO title override
- `thumbnail` — with `url` and `alt_text` if alt text was provided

Only include fields the user provided. Skip the call entirely if none of these were provided.

---

## Step 6 — Confirm

Report back to the user:

- ✅ Post created as draft
- **Post ID:** `<id>`
- **Title:** `<title>`
- **Site:** `<site_name>`
- **Slug:** `<path>` (or "auto-generated by Duda")
- **Tags:** `<tags>` (or "none")
- **Scheduled date:** `<date>` (or "none")
- Remind them: "This post is saved as a draft. To publish it, go to the Duda editor and publish manually — or ask me to publish it and I'll use `publish_blog_post`."

---

## Important rules

- **NEVER call `publish_blog_post`** unless the user explicitly asks you to publish after the draft is confirmed.
- **NEVER invent image URLs** — if a URL is missing, ask for it.
- If `create_blog_post` fails, do not retry with modified content without telling the user what changed.
- If the user's HTML is very long (10,000+ characters), warn them that Duda may have content limits and to verify the post renders correctly in the editor.
